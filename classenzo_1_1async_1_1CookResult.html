Detailed Description

The geometry one cook produced, and when it is ready to be shown.

A cook writes into the result as it goes, one entry per node output. The result is also what the cook reads from, so a node always sees the finished geometry of the nodes it depends on rather than a half written one.

The result is published as a whole. The interface keeps the result of the last cook that finished and only swaps in a new one once that cook is done, so what is on screen is never a mixture of two cooks.

Note
Safe to use from several threads at once. The lock it keeps is only held while an entry is read or written, never while a node cooks.
