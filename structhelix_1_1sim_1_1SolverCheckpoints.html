Detailed Description

template<class State>
struct helix::sim::SolverCheckpoints< State >

Lets a simulation start from the state of a whole frame, and leave states behind.

A solver is always worked out from the frame it starts on, so reaching frame 500 costs 500 frames of steps. With checkpoints, a run asks for the latest state it was handed before and only steps from there, and hands over its own state every few frames so a later run can start from it. The result is the same, bit for bit, as the run from the first frame: the state is the whole of what the next step reads, and the steps are taken in the same order.

The solver counts whole frames from the frame it starts on: index 0 is the starting state and index N the state after N whole frames. What the states are filed under (the settings they were made with, the node they belong to) is up to whoever provides the checkpoints.

◆ interval

template<class State >
std::int64_t helix::sim::SolverCheckpoints< State >::interval = 8

How many whole frames lie between two saved states. A run saves at the multiples.

Note
Saving costs a copy of the state, and a later run steps at most this many frames from the nearest one, so a few frames is the balance for a state of any size.
