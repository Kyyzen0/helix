Detailed Description

Runs cooks on a pool of worker threads.

The scheduler takes a cook as a set of levels. Every node in a level reads only nodes in earlier levels, so a whole level cooks at the same time and the next level waits for it. The nodes of one level are handed out one at a time, so a thread that finishes early picks up the next node rather than sitting idle.

Only one cook runs at a time. Asking for a new cook does not put it behind the running one, it takes its place: the running cook is told to stop and the new one starts as soon as a thread is free. Asking again before that replaces the request once more, so a burst of edits leaves one cook behind rather than a queue of them.

Note
The scheduler knows nothing about nodes. It is handed the levels to cook and a function that cooks one node, so it holds no engine state of its own and can be reasoned about on its own.

void helix::async::CookScheduler::waitForIdle ( )

Waits until no worker is inside a cook.

The workers stop as soon as they see a cook was abandoned, so this waits no longer than the node that is cooking. It is used before the network changes shape, so a worker never holds a pointer to a node that is being taken away.
