Detailed Description

One node's use of the cook cache for one cook.

Before a node cooks, an attempt works out a key that stands for everything the cook depends on, and asks the cache (see nt::CookCache) whether that cook was already done. If it was, the node takes the outputs of that cook and does not cook. If it was not, the node cooks and the attempt files what it produced.

What the key holds
The type of the node, the identity of the packet that arrives at every input (see NodePacket::identity), and the value of every parameter as the cook would read it, an expression evaluated. Then everything that comes from the scene without being a parameter or an input: the keyframes of the node, since a simulation reads a keyed setting at frames before the current one, and the frame, the time and the frame rate. Two cooks with the same key read the same values, so they produce the same geometry (the cooks are deterministic, see VISION.md).
What is cached
Only a node that moves with the scene time: it reads the frame or the time, one of its parameters does (a keyframe, an expression with frame()), or something wired into it does. What does not move with the time is already kept by the node itself, and filing every version of it while a slider is dragged would push out the frames that matter.
Where it does not apply
A cook on a worker thread reads a snapshot of the network, not the live one (see CookContext), and the parameters it would key on are not there to read. Those cooks leave the cache alone.
