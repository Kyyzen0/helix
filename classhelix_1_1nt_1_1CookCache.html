Detailed Description

The memory of the cook: finished cooks of nodes that move with the time, and the saved states of the solvers they run.

Everything a time dependent node produced at a frame is kept, filed under a key that stands for everything the cook depended on (see nt::CookCacheAttempt). Moving back to a frame already visited then costs a lookup instead of a cook. The solvers of the simulation node also save their state every few frames, so a frame not visited yet is reached from the nearest saved state instead of from the first frame.

One process wide budget bounds the whole thing. When it is exceeded the entry used longest ago goes first, whatever node it belongs to. A budget of zero turns the cache off.

Note
Safe to use from several threads: every call takes the one lock, which is never held while a node cooks.
